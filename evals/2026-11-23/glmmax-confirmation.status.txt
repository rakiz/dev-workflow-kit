## Post-mortem of the DNFs (root cause: MY bug, not an outage)

- Symptom: two identical 500 "Unexpected server error", sessions with ZERO
  messages (no user prompt stored) → failure at model resolution, before any
  LLM call.
- Debug run with --print-logs gave the truth:
  `ProviderModelNotFoundError: Model not found: ai-gateway-misc/fw-glm-5-3-flash.
  Did you mean: fw-glm-5.3-flash, ...`
- Cause: the model id was passed with DASHES (`fw-glm-5-3-flash`) — copied
  from the session-title TAG, where the runner's `tr '/. ' '---'` converts
  dots to dashes. The real id has DOTS (`fw-glm-5.3-flash`).
- Red herrings ruled out along the way (all healthy): the gateway (direct
  curl on both /openai/v1 routes + models list: glm-5.3-flash present, key
  valid), the auth (auth.json = portal Secondary key grove_ooF1Yb…, active),
  opencode version (1.19.6 since 11-22, unchanged), env key overrides.
- Standing lesson for the runners: the tag-derivation `tr` makes titles
  ambiguous with the real id — never copy a model id from a session title.
