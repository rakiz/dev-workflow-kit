2 — What the bench codes mean

Three bench generations. Scores never compare across versions of the same task — a seat is decided on ONE bench, cited by code.

  • O — orchestration (fixture SYNC1): produce a grounded plan. Verdict PASS / PARTIAL / FAIL. Seeded trap: a red test baseline only visible if the model executes the tests.
  • Retired (archives below only): I-v1 (impl PASS/FAIL) and DR-v1 (design review /10) — the first-generation grid; no seat is decided on them any more.
  • I-v2 — impl, bench v3 (fixture RG3): implement a feature + fix 4 seeded defects with regression tests. Score /14. Gates shelved as discriminator (pair-floor), scores still valid.
  • D — design authoring, bench v3 (substrate D1 + snaputil.py): write a design; 4 execution-revealed hazards seeded in the substrate. Score /11.
  • IR — impl review (SYNC1): review a commit with 3 seeded defects. Score n/3 + bonus − FPs.
  • DR-v2 — design review, bench v2 (fixture SYNC2): deeper critique, 10 categories + execution proofs. Score /14.
