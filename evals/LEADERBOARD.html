Methodology in brief

  • Four v1 tasks — O orchestration (grounded plan; the red-baseline trap: only a run that executes the tests sees the seeded failing test — it has caught every model ever tested), I-v1 impl (objective: suite green by execution + fix minimalism), IR review (3 seeded defects + bonus findings, false positives counted), DR-v1 design-review (~10 flaw categories in DESIGN.md, FP discipline).
  • Bench v2 (harder fixture, /14, FP triple-counted, proof-by-execution bonus) is the deciding gate for strong-design-review rungs; v1 and v2 scores are never compared — each roster decision cites the bench it was decided on.
  • Honesty blockers are score-zero events — a fabricated green baseline or hallucinated repo structure disqualifies the role regardless of other scores (qwen3p8-max, muse-spark `xhigh`).
  • Delegation rule — an eval arm's cost = parent + ALL child sessions, each child named: a model that delegates inside an eval is scored on the combined labor, never its own tokens alone.
  • Confirmation-run rule — single-run cells are provisional; rung arms get a second run (variance precedents: argon DR-v1 10→8, qwen `low` IR 3/3→2/3, minimax-m3's 3-run oscillation).
  • One matrix, two chart panels — the score matrix holds every measured cell (categorical scores — O/I-v1 verdicts, IR recall — belong in a table, not on a scatter); the main chart plots bench v1 DR-v1 (/10) for every model with per-effort design-review measurements, cost per task on the log X axis, Pareto-pruned per model: an effort cell is dropped when a strictly-cheaper cell of the same model scored equal or better (ties keep the cheapest), so only the strict score/cost frontier per model is drawn; the v2 gate panel below plots the deciding bench (DR-v2 /14) alone — DR-v1 and DR-v2 are never merged on one plot; color = model family (models.json family_hint); a model’s surviving cells are connected in effort order (on the pruned frontier the line itself is the effort-monotonicity evidence — argon’s 8→9 and glm’s 8→6); filled markers = rostered cells, hollow = tested/kept-out; one label per model, at its best surviving cell, with the model’s bench-v2 score appended where measured; interior points are hover-only with exact score/cost/date.
  • Categorical lanes — between the two design-review charts, three compact lane panels give the categorical tasks the same cost axis as the DR charts (log $0.004–0.6 per task): one dotted lane per quality grade (O: PASS/PARTIAL/FAIL; I-v1: PASS/FAIL; IR recall: 3/3, 2/3, ≤1/3), and every model×effort cell that has a verdict and a recorded per-task cost on that task is plotted (rostered solid, kept-out hollow; the FP count is printed beside any marker with FP ≥ 1); exactly one pill per model, anchored at its best grade / cheapest cell, other cells hover-only with exact verdict, cost and date. Cells with a verdict but no per-task figure (verdict-only campaigns, effort-spanning cost ranges — e.g. terra O $0.044–0.047, M3.1 IR $0.0068–0.0107*) stay matrix-only. Data: EVALS.md matrix + evals/2026-11-10|11-06/RESULTS.md; family colors per models.json family_hint.
  • Effort grid — adoption is decided on the full effort×task grid, never a single variant: effort is non-monotone, and the roster assigns one effort per role, not one model-wide grade.
  • Role-decided per-task costs — a rung is decided on the task that rung performs (quality measured and cost paid on that task); the 4-task total is a budget sanity-check only, never an arbiter.
  • Price over speed + lineage — when two models sit in the same quality tier, the cheaper one takes the role; a reviewer is never from its producer's family (one documented exception: the `-alternative` re-review rung).
