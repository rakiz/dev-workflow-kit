Wrote `DESIGN-d1.md` (repo copy only, no subagents, no source changes).

**Design in one line:** materialized per-snapshot directories (`snap-<ts>-<seq>/`, the naming `snaputil.list_snapshots` already expects), built in `.staging/` and published by a single atomic `os.rename`; runs serialized by `flock` on `<root>/.lock` (second run exits 75), readers take shared per-snapshot locks; unchanged files are hardlinked from the last published snapshot (which is the baseline), changed files streamed+hashed into `<dst>.part` then `os.replace`d; retention unpublishes-then-deletes with a grace period; missing/unreadable sources are recorded in the index as `missing` instead of silently skipped.

**Grounding** (each cited with file:line): reuses `synccli.scan_files/build_manifest/changed_files/file_state`, `snaputil.list_snapshots/snapshot_disk_usage/safe_snapshot_path/is_stale`; explicitly overrides `synccli.py:14` (hidden-dir skip → silent data loss), `synccli.py:25` (float mtime → use `mtime_ns`), `synccli.py:62-69` (`copy_file`: swallows `OSError`, whole-file `read()` → 1086 MB RSS on 1 GiB, no mtime, non-atomic write), `snaputil.py:23` (`prune_snapshots`: deletes in place, no reader coordination).

**Budget** — measured here (APFS, Python 3.10.11), not guessed: full 1 GiB / 30 000 files ≈ **11.6 s** warm / 16.5 s cold, budget ≤ 20 s (≤ 45 s with `--fsync`), built term-by-term from measured constants (335 µs/file copy+hash, 873 µs extra per-file fsync, 377 µs hardlink, 6 µs stat, 219 B/index record). Memory O(1) in F (streaming merge, because the dict-based diff measured 1199 B/entry → 1.2 GB at F=1M); disk `S×F×270 B + unique bytes`.

Also documents the index-corruption recovery (re-derived from the tree), the exact miss list of `(size, mtime_ns)` granularity plus `--rehash` cost, the restore contract for the separate tooling, exit codes identical for scheduler and human, a 13-case test plan, and rejected alternatives (blob store, reflinks) with reasons.
