**Keep polling as a candidate, but fix the data-loss and recovery rules before writing code.** `DESIGN.md` promises more than its mechanisms can deliver.

1. **Make destination writes atomic and define crash recovery (§§ Integrity–Lock scope).** Re-statting the source after writing directly to `dst` can trigger a retry, but readers can already have seen a partial file, and a crash can leave it there. Stream to a temp file beside the destination, validate the source, then atomically replace the destination. Hold an OS-backed lock for the daemon’s lifetime, including state commits. Define when updates are durable and how recovery handles an interrupted journal append or a crash between publishing a file and recording it. Replay cannot repair a torn manifest unless the journal contains enough history to rebuild it.
2. **Distinguish “deleted” from “couldn’t scan” (§§ Deletions, Errors).** An unreadable directory or temporarily unavailable source can look like a mass deletion. Only delete from `dst` when the relevant part of `src` was scanned successfully. Include deletions in the recovery protocol.
3. **Fix change detection before committing to the legacy manifest (§§ Rejected alternatives, Rollout).** An equal-size rewrite within the same second can be missed indefinitely. Use nanosecond timestamps at minimum and decide how to migrate legacy state. If edits that preserve timestamps must be detected, metadata alone is insufficient; hashing only metadata-flagged files won’t catch them either.
4. **Replace the latency and backlog promises with a policy you can test (§§ Scan–Backpressure).** A file that changes on every scan can remain pending indefinitely; a build burst can take multiple cycles to drain while new work arrives. Separate scanning from copying, budget copy work, and define what happens to files that never settle. Benchmark the *whole cycle* on representative trees under idle and build load: a 500 ms interval means roughly 100,000 file stats per second at idle alone, before traversal and manifest I/O. Commit state only when dirty, and track scan duration and oldest pending age.
