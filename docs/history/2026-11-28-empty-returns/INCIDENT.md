INCIDENT REPORT — dead subagent sessions (empty returns) — Pete P1 wave 3, 2026-11-28
1. What happened (the raw record)
Five subagent sessions returned state="completed" with an empty result payload and zero file writes (worktree-verified each time). All were implementation dispatches of wave 3b's cell-blit scope. Timeline:
(#3.3) fresh strong-code (minimax), large brief (2 engine modules + bench + gate + table): EMPTY. Recovery resume → full report: read widely (design sections, all probe/engine files, probe.sh 1138 lines in full, ~600 lines of probe_check.py, the sibling oracle project), derived the straddle geometry analytically; own diagnosis: context exhausted "while producing a long report".
(#3.4) fresh strong-code-alternative (claude) — escalated per kit §1, same scope + 3.3's salvaged notes inlined: EMPTY. Zero writes. (Not resumed — stop-and-state instead.)
(#3.8) fresh strong-code, large (3b impl-1, halved scope vs 3.3, salvaged notes inlined): EMPTY. Recovery resume → full report: completed the geometry verification by execution (throwaway C program → printed 224-cell segment table) and produced a complete settled plan; own diagnosis: "I spent the session in an extended design deliberation (in reasoning, not in files)… ended with zero source writes… reasoning volume ≫ output."
(#3.9) fresh strong-code, SAME scope + the settled plan inlined + "write, do not re-deliberate": EMPTY. Zero writes.
(#3.10) fresh strong-code, tiny (infra probe: write 1 file, reply 1 line): WORKED — file written, reported. Harness proven healthy.
(#3.11) fresh strong-code, small (one asm module, minimal brief): EMPTY. Recovery resume → the decisive report: the session did ALL verification (including replicating the screen law in a throwaway Python script outside the repo, catching a Z1 stale-exemption trap, listing invalid Z80 forms), finished the complete file design in reasoning down to instruction level, and "the session ended before the write step, not a tool rejection" — zero write tool calls ever issued.
Counter-example controls: two earlier sessions the same day (wave 3a parts A and B) were fresh strong-code sessions with comparable brief sizes and succeeded normally.
2. What was happening (diagnosis, as it evolved)
v1 (after 3.3): "scope too large per session" — falsified: 3.11 died on a one-module scope.
v2 (after 3.9): "infrastructure/harness failure" — falsified: the 3.10 tiny probe worked.
v3 (final, after 3.11's recovery): budget exhaustion via verify-before-write. The briefs (written by the orchestrator) front-loaded mandated reading and verification ("read §X, cross-check the law, execution-verify the geometry, study the wiring pattern"). Each demand was individually justified; together they legitimized hours of preparation. The sessions honored the brief literally, spent their whole budget preparing, and the harness ended them before the first write tool call — hence completed + empty payload + zero side effects. The recovery resumes always worked (2/2) because a small ask on an already-populated context is cheap.
Aggravating factor: every rescue brief ADDED context (salvaged notes, more warnings, more discipline instructions) — monotonically increasing the ingest cost, the opposite of what was needed.
Note the masking: state="completed" + empty payload is indistinguishable from a lost report without a worktree inspection. Detection required the §7 procedure every time.
3. The solution attempted (and its result)
1. Execution-first briefs: the brief's literal instruction becomes "your FIRST tool call must be a WRITE"; the order is write → verify → fix. All settled facts are INLINED in the brief (no source-pointing for things already derived); mandated reading capped to the exact files/sections actually needed.
2. Rung REDUCTION to cheap-code (claude) for transcription: the recoveries had completed the design at instruction level, so the remaining work was transcription. The kit's ladder exception (strong at design time) had already been honored — the design existed; keeping the strong rung only preserved its over-verification behavior.
3. Micro-dispatching: scope split into 3 short briefs (tile_blit.asm / drain cell path / bench+gate), each with checkpointed verification (build-verify between ordered writes) and an explicit "return a factual report, never an empty message" stop rule.
Result: 6/6 sessions healthy since the change, zero empty returns. Side benefit: two real defects found and proven by the sessions themselves; both fixed by resumed author instances; final state green.
4. Proposals for the kit (extractable, §9 format)
- P-A — SKILL.md §1 (briefing/delegation bullet), add: an implementation brief orders its writes (first write before any mandated reading), inlines the settled facts instead of pointing at sources to re-derive, and caps mandated reading at the files actually touched. Evidence: 5 dead sessions vs 6/6 healthy after; the 3.11 recovery report is the proof artifact. Acceptance: a new agent run on a multi-artifact task issues its first write before its third read.
- P-B — SKILL.md §7 (recovery), add the decision table: empty return + zero writes → worktree inspection → ONE resume-for-facts → then choose: (i) the recovery produced a complete design → RE-ROUTE the remaining work to a transcription rung with an execution-first brief (the ladder is not only upward); (ii) no salvage → then escalate per §1. Evidence: the 3.4 escalation (by-the-book) died identically; the 3.12 rerouting (off-ladder) succeeded. Acceptance: the written rule names both branches.
- P-C — dead-session signature (one line in §7): state=completed + empty payload + zero writes = budget exhaustion, never assumed a lost report; NEVER re-dispatch the same brief unchanged (we did twice, 3.4 and 3.9 — both died).
- P-D — optional harness note: a completion whose payload lacks the briefed attempt-id echo is detectably abnormal; cheap to check before any dispatch decision.
